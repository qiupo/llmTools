# llmTools v0.5.1

`v0.5.1` focuses on a clear first-run model experience, accurate feature readiness, and actionable recovery when a model or runtime is missing.

## 功能与修复

- 模型首次配置：模型页默认进入“开始使用”，逐项显示文本、网页翻译、OCR、字幕、会议和 TTS 的真实可用状态。
- 单一推荐入口：文本、OCR、ASR 和 TTS 各提供一个首次安装首选；其他兼容模型与辅助 runtime 收入高级折叠区，已有默认选择不会被覆盖。
- 无模型状态：完全没有本地模型和远程 Provider 时，所有处理入口会明确禁用并指向模型设置；设置、权限、Provider 配置和已有历史仍可使用。
- 可用性校验：空目录、丢失路径、失败或加载中的模型不再解锁功能；外接模型盘暂时离线时保留用户选择，文件恢复后可重新使用。
- 精确依赖提示：基础 OCR、OCR 后处理、原文字幕、字幕翻译、会议转写、会议纪要、单旁白 TTS 和多角色 TTS 分别按真实依赖展示 Ready、Partial 或 Unavailable。
- 下载指引：为 Qwen3.5、GLM-OCR、Qwen3-ASR 和 VoxCPM2 提供准确模型 ID、官方页面、镜像、复制命令和添加目录说明；Fast MT、fastText 与 pyannote 继续作为可选辅助 runtime 管理。
- 网页翻译诊断：bridge 状态现在包含功能与模型矩阵；功能关闭返回 `403`，当前 LLM/Fast MT 路由缺少依赖时返回 `409 model_not_configured`，扩展会禁用对应操作并显示修复入口。
- 启动资源控制：Fast MT 启动检查只验证本地文件与 Python 模块，不再为了显示 Ready 自动启动常驻 sidecar。
- 回归覆盖：新增全新 HOME、空模型目录、校验失败、外接路径恢复、推荐策略、Fast MT 域名覆盖和浏览器扩展缺模型状态检查。

## 使用方法

1. 从本 Release 下载 `llmTools-v0.5.1-macos-arm64.zip`，解压后把 `llmTools.app` 移到 `/Applications` 或其他可信目录。
2. 首次启动后打开“设置 -> 模型 -> 开始使用”，只为计划使用的功能安装一个推荐模型，不需要下载全部支持模型。
3. 文本、OCR 和 ASR 模型下载完成后，在“模型管理”中添加整个模型目录；ASR 还需要执行对应的 runtime 健康检查或修复。
4. TTS 可以在“开始使用”页面一次安装独立 runtime 和 VoxCPM2 模型；多角色分析还需要一个本地 GGUF 或 MLX 文本模型。
5. 网页翻译扩展仍为开发通道；升级后请在 `chrome://extensions` 或 `edge://extensions` 重新加载本 Release 附带的 unpacked extension。

## 推荐起步组合

- 文本：`lmstudio-community/Qwen3.5-0.8B-MLX-8bit`
- OCR：`mlx-community/GLM-OCR-4bit`
- ASR：`mlx-community/Qwen3-ASR-0.6B-8bit`
- TTS：`mlx-community/VoxCPM2-bf16`

## 说明

- Release 包含 runner、安装脚本和 Chromium 扩展，但不包含任何模型权重。
- 远程文本或视觉 Provider 可以替代相应的一般任务；会议纪要、多角色 TTS 分析和语音处理仍遵守既有 local-only 边界。
- Provider API key 继续保存在本地 `model-registry.json`，不接入 macOS Keychain。
- Chromium 扩展仍为手动加载的开发版本，不是 Chrome Web Store 分发版本。
- macOS app 使用 ad-hoc 签名且未 notarize。
